# 公众号长期忽略规则与结构化视觉规划设计

## 目标

让用户可以忽略无价值配图候选，并把该决定作为当前用户的长期偏好用于后续公众号拆文；同时把表格、流程和对比内容先编译成可验证的视觉规划，再生成提示词和图片，减少空表、机械抄字、顺序错误和无关角色。

## 范围

1. 仅修改微信公众号写作流程，不影响小红书模块。
2. 忽略规则归属当前用户，默认影响该用户后续所有公众号文章；不得影响其他用户。
3. 用户可以停用或删除长期规则，也可以只恢复当前提示词。
4. 已生成图片被忽略后从文章正文移除，但 AI 素材资产和费用记录必须保留。

## 长期忽略规则

新增 `WechatMpPromptIgnoreRule`，保存 `user_id`、来源提示词、结构类型、概念签名、来源文章/提示词、状态和时间。点击“忽略类似内容”时：

- 当前提示词状态改为 `ignored`，从生成队列和正文占位符中移除。
- 从段落结构提取概念词和关系边，生成稳定签名。
- 规则在下次拆文选候选之后、调用提示词模型之前执行。
- 完全相同签名直接过滤；同结构类型的概念包含度达到 `0.78` 才过滤，避免宽泛关键词误伤。
- 命中结果记录规则 ID，前端显示“因历史忽略规则跳过”。

“只忽略本条”不创建长期规则；“恢复”只恢复当前提示词；停用规则后，未来文章可再次生成类似候选。

## 结构化视觉规划

每个结构化候选生成 `VisualPlan`：

```json
{
  "kind": "comparison",
  "title": "确认范围与质量控制",
  "columns": ["确认范围", "质量控制"],
  "rows": [
    {"label": "关注点", "values": ["外部接受", "准确与质量"]},
    {"label": "执行方", "values": ["外部干系人", "内部质量部门"]},
    {"label": "时机", "values": ["阶段末", "不固定"]}
  ],
  "relations": [{"from": "质量控制", "to": "确认范围", "label": "先质检，再验收"}],
  "character_role": "右下角单只解说员"
}
```

规划类型至少包含 `flow`、`comparison`、`matrix`、`classification`、`semantic`。Markdown 的 `|` 只作为单元格分隔符，分隔行不得进入内容。标准表格和无首尾竖线表格均需解析；行列数量不一致时不得进入生图。

## 提示词编译

提示词不再直接拼接原始表格，而由 `VisualPlan` 编译：

- 流程图必须保留节点数量、原始顺序和分组。
- 对比图以两栏或泳道呈现，关系边单独描述，不生成待填写空表。
- 长单元格转成短标签、图标、物体或状态，但不得改变语义。
- 知识结构占画面 80-90%，确认形象最多一只、占 10-20%，只在边缘辅助说明。
- 禁止标题、比例、提示词、说明文字、水印和无关装饰进入图片。

生成前校验必须证明：源单元格全部被规划引用、列数一致、流程顺序一致、关系边合法、角色数量上限为一。校验失败时返回可编辑错误，不调用图片模型。

## 图片生成与质量状态

图片生成保存 `visual_plan` 和 `quality_report`。第一阶段质量门禁以确定性规划校验为准，并在 UI 显示检查项；结构化信息图后续切换到确定性 SVG 渲染时复用同一规划接口。生成失败或规划不完整不得标记为 `generated`。

Article 14 的验收规划：

- 六过程表格生成六节点流程，并把前四项归入规划、后两项归入监控。
- 产品范围/项目范围生成双栏对象与完成判断依据对比。
- 表格形式/树形结构生成两个结构示意，不机械抄写整句。
- 确认范围/质量控制生成内部质检到外部验收的先后关系及三项差异。

## API 与界面

- `POST /articles/{article_id}/prompts/{prompt_id}/ignore`，请求 `scope=current|future_similar`。
- `POST /articles/{article_id}/prompts/{prompt_id}/restore`。
- `GET /prompt-ignore-rules`、`PATCH /prompt-ignore-rules/{id}`、`DELETE /prompt-ignore-rules/{id}`。
- 提示词卡增加“忽略”菜单和“视觉规划”预览；页面增加“已忽略”和“忽略规则”抽屉。
- 状态联合类型增加 `ignored`；图片队列必须跳过 `ignored`。

## 验收

- 用户 A 的规则不影响用户 B。
- 长期规则在文本模型调用前过滤，并且命中时 Token 为零。
- 当前忽略会清除正文占位符，但不删除历史资产。
- 无首尾竖线表格可正确解析；Markdown 分隔行不进入视觉规划。
- Article 14 的 #90-#93 规划通过行列、顺序、关系和单角色校验。
- 后端全量测试、前端构建、迁移和 Atlas 健康检查通过。
