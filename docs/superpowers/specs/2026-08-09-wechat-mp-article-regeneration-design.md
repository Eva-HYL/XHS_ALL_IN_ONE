# 公众号文章返回修改与原文重新生成设计

## 目标

在“编辑与预览”步骤增加返回入口。用户返回第一步后，可以修改素材、补充想法、标题、主题、读者、语气和形象，并重新生成当前文章。重新生成必须覆盖同一篇文章并增加修订号，不得在文章列表创建重复稿件。

## 方案比较

1. **同文章原位重新生成（采用）**：新增明确的重新生成接口，保留文章 ID，统一处理修订、素材关系、旧提示词、旧图片和微信草稿失效。行为最符合用户预期。
2. **重新创建一篇文章（不采用）**：实现简单，但会留下重复文章、重复素材使用记录和难以判断的发布状态。
3. **先生成内容再调用通用 PATCH（不采用）**：通用 PATCH 不掌握写作来源、模型用量和封面失效语义，容易产生半更新状态。

## 页面行为

- “2. 编辑与预览”增加 `返回修改写作要求` 按钮，返回步骤 1。
- 首次生成文章后不再清空已确认素材、待选素材、想法和写作简报。
- 返回后保留用户上次确认的素材和简报；来源发生变化时继续沿用现有“来源已变化”提示，不自动覆盖人工修改。
- 当前已有文章时，第一步主按钮显示 `重新生成文章`；没有文章时仍显示 `生成文章`。
- 重新生成期间禁用简报和正文按钮；成功后继续停留在“编辑与预览”，刷新标题、正文、排版、修订号和费用。
- 重新生成失败时保留旧文章、当前输入和简报，允许重试。

## 后端接口

新增：

`POST /api/platforms/wechat-mp/articles/{article_id}/regenerate`

请求继续使用 `WechatMpArticleCreateRequest`，避免出现两套写作字段。接口必须先校验文章归属，再校验素材和形象归属。

服务端先完成模型调用和响应校验，模型成功后才在一个数据库事务中更新：

1. 替换标题、Markdown、微信 HTML、摘要、封面提示词和插画技能。
2. 删除旧文章素材关联并写入本次已确认素材关联。
3. 删除旧段落与旧提示词；正文图片资产保留为历史 AI 资产，但解除 `prompt_id` 关联。
4. 旧封面资产保留为历史 AI 资产并将状态改为 `stale`，不再作为当前封面。
5. 调用 `invalidate_synced_drafts(..., next_status="layout_ready")`，修订号只增加一次，已同步微信草稿变为过期。
6. 新正文模型用量写入 `UsageRecord(step="write_article")`，文章累计费用在原总额上增加，不覆盖历史费用。

任何异常都回滚数据库修改。已经生成并存储的历史 AI 图片文件不删除。

## 资产与状态

- 当前文章资产展示只接受 `status="generated"`；`stale` 封面仍可在公众号素材库中查看。
- 正文重新生成后状态为 `layout_ready`，旧提示词和正文图片不再出现在当前写作队列。
- 后续重新生成提示词、正文图和封面继续使用现有流程。
- 已提交或已发布的历史任务不删除，但因文章修订号变化不能继续作为当前版本发布依据。

## 测试

- 后端：同一文章 ID、修订号加一、正文替换、素材关联替换、旧提示词删除、正文资产解绑、旧封面变 `stale`、草稿同步变 `stale`、费用累计、跨用户 404。
- 前端：编辑页存在返回按钮；首次生成后来源状态不被清空；已有文章时调用重新生成 API 而不是创建 API；成功后仍进入编辑预览。
- 回归：写作简报、图片队列、文章编辑、生产构建和 Atlas 健康检查。

## 验收标准

- 用户可从“编辑与预览”返回第一步并看到原素材与简报。
- 点击重新生成后文章 ID 不变、修订号增加且列表不产生重复文章。
- 旧提示词、正文图和封面不会继续作为当前版本内容。
- 历史 AI 图片资产仍可在素材库追溯。
- 重新生成失败不破坏旧文章。
