# 公众号正文配图一键生成设计

## 目标

在公众号写作页“编辑提示词并生成图片”步骤增加一键生成全部正文配图的入口。复用现有串行队列，不新增后端批量任务接口，不改变单图生成、资产保存、费用统计和文章回填契约。

## 入口与状态

- 按钮放在图片模型选择和费用说明下方、封面卡片上方，文案为 `一键生成全部正文图片（N）`。
- `N` 是当前仍可入队的提示词数，不包含已生成、已忽略、`none`、正在生成和已排队项。
- 队列运行时按钮显示 `正在按队列生成（剩余 N）`。当无可入队项时禁用。
- 单图按钮继续可用，与批量入口共享同一队列。

## 入队规则

点击后按页面中的提示词顺序扫描，只追加满足以下条件的项：

1. `skill_name !== "none"`。
2. `status` 不是 `ignored` 或 `generated`。
3. 当前没有对应正文图资产。
4. 不是当前 active 项，也不在 `imageQueueRef.current` 中。

`prompt_ready` 和 `failed` 都允许入队。批量操作不重新生成已完成的图片；需要替换已生成图片时仍使用该卡片的“重新生成正文图片”。

## 执行与错误

- 所有项仍由 `runImageQueue` 串行处理，只有 `activeImagePromptId` 对应卡片显示 loading，其余项显示 queued/排队中。
- 每张图在生成前先调用 `updateWechatMpPrompt` 保存当前可编辑提示词。
- 单张失败时将对应提示词标记为 `failed`，显示原有错误提示，但不中断后续队列。
- 单张成功时继续按现有规则更新资产、提示词状态、文章内容和费用。
- 队列结束后清空 active 和 queue 状态，按钮重新根据当前资产与提示词计算数量。

## 实现边界

- 仅修改公众号 writer 页的队列入口和状态显示。
- 不新增后端 API、数据库表、批量费用记录或并发调度器。
- 不将封面图加入正文图批量队列。
- 不自动重试失败项；用户可再次点击一键生成或单图按钮重试。

## 验收

- 页面显示一键生成按钮和当前可入队数。
- 点击后可生成项按原顺序进入现有队列，不重复入队。
- 已生成、已忽略、`none` 和已排队项被跳过。
- 同一时刻只有一张图请求在执行，只有对应卡片 loading。
- 某张图生成失败后，后续图仍继续执行。
- 前端构建通过，writer 页相关回归测试通过。
