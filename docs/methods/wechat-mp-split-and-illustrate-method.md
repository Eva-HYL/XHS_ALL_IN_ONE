# 微信公众号拆文生图方法

## 方法版本

- 当前版本：`v1.3.0`
- 适用范围：微信公众号文章拆文、配图规划、提示词生成、结构图渲染和质量验收。
- 版本绑定：拆文段落、视觉计划、提示词指纹和图片资产均记录方法版本。方法升级后，旧提示词不再被当作当前规则的可复用结果。

## 一、拆文

1. 先按 Markdown 标题路径和原文顺序分块，每块保留原文、清洗文本、标题路径、原文位置和稳定指纹。
2. 不把代码块、`details/summary` 等 HTML 容器、尺寸、比例、水印、提示词说明或编辑器操作当成配图内容。
3. Markdown 表格不论是否带 `---` 分隔行，都必须先解析列、行和单元格归属，不允许把 `|` 当作普通文字送去生图。
4. 含 `→`、`->`、`⇒` 等连接符的三步以上内容识别为有序流程；数字序号表格按原顺序生成流程和原文分组。
5. 连续的“名称：内容”映射识别为分类结构。普通段落只在具有明确问题、方法、原因、结果、步骤、对比、变化或关系时成为语义配图候选。
6. 过短、营销收尾、与已选段落高度相似或没有可视化信息的内容不生成提示词，节省 token 和图片额度。
7. 用户点击“忽略”时按选定的作用域记录；当前文章规则不自动扩大为全局规则。

## 二、视觉计划

### 结构型内容

- `flow`：保留每个原文节点、顺序、箭头和原文分组，节点不得合并、换序、重复或补写。
- `comparison`：两个数据列生成双栏对比卡；每个行标签在左右单元中对应同一维度，不串列、不改写。
- `matrix`：单列或多列知识矩阵；单列表不生成空白行名列，每行直接显示原行名和原值。
- `classification`：类别和内容一一对应，不把类别抽象成无关插画。

所有结构计划必须携带：`method_version`、`layout_style`、`source_cells`、`template_copy=[]` 和 `character_role=边缘单只解说员`。视觉计划不保存派生的通用标题。

### 语义型内容

- 提示词只描述需要解释的文章概念、核心动作、对象、状态变化和空间关系。
- 不重复 Markdown、HTML、标题、尺寸、比例、水印、提示词或角色外观定义。
- 没有有效视觉信息的候选可不返回，不为了凑配图数而虚构画面。
- 一次批量生成语义提示词，不重复发送完整角色定义，以 `@形象名` 引用已确认的形象资产。

## 三、生图

1. 结构图使用确定性 Pillow 渲染，不调用图片模型；只绘制 `source_cells` 内的文章内容。
2. 禁止渲染“对比关系”、“结构矩阵”、“流程关系”、“分类结构”等模板标题，也禁止渲染模板说明、提示词和参数。
3. 知识内容是画面主体。已确认形象最多一只，只在右下角或边缘辅助讲解，占比不超过 15%，不遮挡文字、箭头或单元格。
4. 表格采用知识卡片布局：原列名作为顶部标题，原行名作为单元内小标题，原值紧随其后；图标只用于帮助扫读，不取代文章知识。
5. 语义插画不显示文字，不添加无关道具、多余角色或背景故事。封面必须围绕文章核心主题组织画面，不允许只放一只形象。
6. 每次生成均保存为 AI 资产并回填当前文章；单图队列串行执行，只有当前任务显示 loading。
7. 同一方法版本、同一形象锚点且文本指纹一致时才可直接复用。类似资产复用不得跨形象或绕过四视图确认。

## 四、自动验收

每个结构视觉计划必须同时通过：

- `source_coverage`：源单元格与计划单元格完全一致。
- `order_valid`：有序流程不换序。
- `single_character`：角色规则为边缘单只解说员。
- `article_only_copy`：无派生标题，`template_copy` 为空。
- `layout_valid`：布局为 `article_knowledge_cards_v1`。
- `method_current`：计划使用当前方法版本。

任一项失败时不进入生图。确定性结构图的资产元数据必须记录方法版本、布局版本、渲染标签、渲染单元格、形象是否成功渲染，且不新增 `image_gen` 用量。

## 五、人工可编辑边界

- 用户可修改提示词的具体画面，但角色定义始终来自 `@形象名` 对应的已确认形象资产。
- 结构图中需修改的事实应先修正文章原文，再重新拆文和生成计划；不在渲染器内悄悄改写知识。
- 用户可忽略不需要的候选、重新生成单张图或在发布前预览；历史资产保留，不覆盖。
